# 分工與時程

期中報告後的版本，已納入助教的兩點建議（坡度、大眾運輸）。兩項新增都屬於路線推薦，主要由 Member D 負責，不影響聲音處理這個主軸。

## 分工

| 成員 | 角色 | 原本的工作 | 期中後新增 |
|---|---|---|---|
| A | 整合 | 系統架構、後端、語音辨識與合成 API 串接、各模組整合 | 串接公車資料來源（TDX 或地圖服務的大眾運輸規劃） |
| B | 音訊輸入 | 重取樣、語音偵測、頻譜相減降噪、音量正規化 | 無 |
| C | 音訊輸出與評估 | 聽力補償 EQ、響度正規化；錄製測試語料、字元錯誤率與頻譜圖實驗 | 無 |
| D | App 邏輯與資料 | 意圖擷取、廟宇資料整理、路線評分 | 坡度項；步行超過上限時改推薦搭公車 |
| E | 介面與實地 | 大按鈕介面、實地錄音與長輩試用、USR 文件與期末簡報 | 推薦卡片加坡度標籤與「搭公車」方案；踏查時記錄陡坡；確認當地公車班次 |

## 新增工作細項

### 坡度

1. 選定高程資料來源，確認能查到民雄、新港的海拔。
2. 沿路線取點，算每段坡度；只計上坡，超過門檻才重罰。
3. 評分公式改為 `cost = w1·distance + w2·stairs + w3·slope − w4·benches`，坡度權重依使用者行動狀況（例如拄拐杖）調整。
4. 實地踏查補標高程資料抓不到的短陡坡。

### 大眾運輸

1. **最低目標**：步行超過上限（例如 500 公尺）時，語音提醒「走路太遠」並改推薦較近的廟。
2. **完整目標**：查出「走到站牌 → 搭公車 → 走到廟」的方案，只計實際步行距離加等車時間，和純步行方案比較後推薦。
3. 語音回覆包含站牌位置與下一班時間；等車太久就不推薦搭車。

## 六週時程

| 週次 | 主要工作 | 期中後新增 |
|---|---|---|
| 第 1 週 | 實地錄測試語料、整理廟宇資料、API 選型 | 一併選定高程與公車資料來源；查當地班次 |
| 第 2–3 週 | 輸入前處理與輸出處理以 Python 離線完成並做實驗 | D 同步完成坡度項 |
| 第 4 週 | App 邏輯＋介面，串成端到端原型 | 加入距離上限提醒（大眾運輸最低目標） |
| 第 5 週 | 實地測試、字元錯誤率比較、修正 | 有餘力再做完整的搭公車方案 |
| 第 6 週 | Demo 影片與期末發表 | 無 |

大眾運輸的完整目標排在第 5 週並列為有餘力再做，避免壓縮聲音處理的時間；第 4 週的最低目標已足以回應助教建議。
