# 分工與時程

2026-11-22 版本。期中後依助教建議加入坡度與大眾運輸；因為沒有時間實地考察，坡度改用地形資料計算，評估改用室內錄音加網路噪音。設計原因見 [project-log.md](project-log.md) 第 6、8、9 節。

| 成員 | 角色 | 工作 |

| A | 整合 | 系統架構、後端、語音辨識與合成 API 串接、各模組整合；串接公車資料來源（TDX 或地圖服務的大眾運輸規劃） |
| B | 音訊輸入 | 重取樣、語音偵測、頻譜相減降噪、音量正規化 |
| C | 音訊輸出與評估 | 聽力補償 EQ、響度正規化；噪音混合程式（依訊噪比混合）、字元錯誤率與頻譜圖實驗 |
| D | App 邏輯與資料 | 意圖擷取、廟宇資料整理；地形高度剖面與 Tobler 步行時間評分、陡下坡懲罰、休息點加分；步行太久時改推薦搭公車 |
| E | 介面與資料蒐集 | 大按鈕介面（推薦卡片顯示步行時間、坡度與休息點）；錄製華語乾淨語音（可請身邊長輩幫忙，事先說明用途）；下載整理噪音素材並記錄授權；確認當地公車班次；USR 文件與期末簡報 |

## 路線評分（D）

`cost = 預估步行時間 + w × 陡下坡長度 − 休息點加分`

1. 選定地形資料來源（內政部 DEM 或高程 API），確認能查到民雄、新港的海拔。
2. 沿路線每隔約 20 公尺取海拔，平滑後算每段坡度。
3. 每段用 Tobler 公式 `6 × e^(−3.5 × |坡度 + 0.05|)` 算速度，乘上長輩速度係數（暫定一般 0.8、拄拐杖 0.55），加總成預估步行時間。
4. 坡度陡於 −8%（暫定）的下坡依長度加懲罰。
5. 從 OpenStreetMap 取休息點（座椅、公園、便利商店、廟宇）加分；路線上若有標記階梯，只做語音提醒、不計分。

## 大眾運輸（D、A）

1. **最低目標**：預估步行時間超過上限（例如 15 分鐘）時，語音提醒「走路太遠」並改推薦較近的廟。
2. **完整目標**：查出「走到站牌 → 搭公車 → 走到廟」的方案，只計實際步行時間加等車時間，和純步行比較後推薦。
3. 語音回覆包含站牌位置與下一班時間；等車太久就不推薦搭車。

## 評估（C、E）

1. E 在室內錄華語乾淨語音指令（例如「我想去拜拜」），並附正確逐字稿。
2. E 依 [project-log.md](project-log.md) 第 8 節下載 9 段噪音（廟會、鞭炮、街道各 3 段），轉成單聲道 16 kHz，記錄授權與標註。
3. C 寫混合程式，依 0、5、10 dB 三種訊噪比把噪音混進乾淨語音。
4. 同一個語音辨識 API 分別辨識「原始混音」與「前處理後」，比較字元錯誤率；另做處理前後的波形與頻譜圖。
5. 輸出端：請幾位長輩比較聽力補償前後哪個比較清楚。

## 六週時程

| 週次 | 工作 |
|---|---|
| 第 1 週 | API 選型；選定地形、路網、公車資料來源；錄乾淨語音、下載噪音素材；查當地公車班次 |
| 第 2–3 週 | B、C 以 Python 離線完成輸入前處理與輸出處理；C 完成噪音混合程式；D 完成高度剖面與步行時間評分 |
| 第 4 週 | App 邏輯＋介面，串成端到端原型；加入步行太久的提醒（大眾運輸最低目標） |
| 第 5 週 | 9 種測試條件的錯誤率比較、長輩聽感測試、修正；有餘力再做完整的搭公車方案 |
| 第 6 週 | Demo 影片與期末發表 |

大眾運輸的完整目標列為有餘力再做，避免壓縮聲音處理的時間。
